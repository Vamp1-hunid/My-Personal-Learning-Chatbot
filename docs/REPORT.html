QuantaKai: a private, offline, book-grounded assistant for a student laptop

Project report by Mulenga Mwamba, Bachelor of Science in Data Science, Mulungushi University. November 2026.

1Summary

QuantaKai is a personal AI assistant that runs completely on an ordinary Windows laptop (AMD Ryzen 5 PRO 3500U, 16 GB RAM, no dedicated graphics card). It combines a local language model (Qwen2.5-3B-Instruct, 4-bit) served by llama.cpp with a hybrid search engine over the owner's own books, a long-term memory, web search on demand, creative writing, code execution, picture and document reading, and offline speech in both directions. Everything lives in one portable folder with its own Python runtime, so it can be copied to another drive or PC and still run.

2Background and goals

An earlier group project (Group G014, a book-grounded RAG chatbot using FAISS, Qwen2.5-0.5B and a Python 3.11 virtual environment) stopped working on the author's new laptop: its virtual environment pointed at a Python installation that no longer existed, and FAISS had no wheels for newer Python versions. QuantaKai was built from scratch as a personal project with these goals, set by the owner:

  • A more premium-looking, faster and sharper offline chatbot that runs smoothly on this laptop.
  • Answers questions from many books (20 to start, more later) in a way the owner can understand.
  • More than a notes bot: personal conversations, learning new facts as conversations go on, and a study mode on request.
  • Manual switching between models inside the app, each model at most 5 GB; the option to load an abliterated model.
  • A portable folder on the Desktop that keeps working if moved.
  • A complete HTML build guide listing every program, link, folder and file.
  • Later additions: a nickname, faster stoppable voice, a light default theme, custom wallpaper, story and character writing, an animated mascot that dresses for each mode, highlight-to-read/explain, and a much richer subject list.

4Architecture

Four processes cooperate on the same machine. The browser shows a single HTML page served by a small Python web server. The server owns all logic (prompt building, search, memory, persistence) and talks over HTTP to two llama-server processes: one for the chat model and one for the embedding model. Optional helper processes provide speech recognition (whisper.cpp), speech synthesis (Piper, Kokoro) and picture text recognition (Windows OCR through PowerShell).

6Implementation

Engine management

engine.py starts each llama-server with an explicit command line, waits for /health, and records the process number. A Windows Job Object with kill-on-close guarantees that closing the console window also ends the engines, preventing gigabytes of orphaned memory. Leftover processes from a crash are stopped at the next start, but only after checking the process name, because Windows reuses process numbers. Models are validated by their GGUF magic bytes and size before loading; vision projector files are matched to their model by name.

Retrieval

Books are split into 180-word passages with 40 words of overlap, keeping page ranges. Retrieval combines dense similarity (bge vectors, with the query instruction prefix) and BM25 keyword scores using reciprocal rank fusion, which fixes the two typical failures of each method alone: vectors miss exact names and formulas, keywords miss paraphrases. Results are restricted to the most relevant subject(s), near-duplicate overlapping passages are removed, and a spelling corrector built from the books' own vocabulary repairs typos in queries. Passages below a minimum meaning score are dropped unless they have a strong keyword match, and the prompt instructs the model to refuse when the passages do not contain the answer.

Subjects

80 subjects in 11 groups (Cybersecurity, Data & AI, Programming & Software, Computers & Electronics, Maths & Science, Faith, Fiction & Literature, Non-fiction, Life & Skills, Study, Other). A book's subject comes from, in order: the owner's choice; title keywords for technical subjects (ordered from specific to broad, so "Python for Cybersecurity" is Cybersecurity); otherwise the nearest subject description to the book's average vector. All file names in the owner's books folder were used to test the title rules.

Memory

A language model cannot update its weights during use, so memory is retrieval: short facts with vectors in memory.json, the most relevant of which are inserted into the system prompt. Facts are added explicitly ("remember that…") or by a background extraction prompt after each chat reply, with near-duplicates rejected at cosine similarity 0.92.

Prompting and context budgeting

Each mode and style has its own system prompt. The context window (4096 tokens) is budgeted with a 3.5 characters-per-token estimate: system prompt, retrieved context, question and the answer's token cap are reserved first, and older history is dropped from the start until everything fits. Voice-mode answers are capped at 220 tokens and instructed to sound spoken; long-form styles (Code, Teach, Quiz, Create) are never shortened.

Streaming, stopping and editing

Answers stream as Server-Sent Events. Closing the connection stops the engine from generating, and the partial answer is still saved. Every question and answer share a turn tag, so Retry and Edit rewind the conversation precisely. A global lock serialises generation, which suits a single local engine.

Voice

The page records 16 kHz mono WAV and whisper.cpp transcribes it. For reading aloud, the page sends each finished sentence while the answer is still streaming, and plays the returned WAV clips gaplessly with the Web Audio API, so speech starts after the first sentence instead of after the whole answer. Piper stays loaded as a long-lived process; Kokoro is kept loaded by a separate worker process that calls the sherpa-onnx C library through ctypes, which removed a reload of the 114 MB model for every sentence. Kokoro is disabled automatically in Auto mode if it runs slower than 2.5 times real time.

Interface

The interface is one HTML file with five pages. All model output is HTML-escaped before a small Markdown renderer runs, so model text cannot execute in the browser. Quiz answers follow a strict text format that the page parses into an interactive quiz with flashcards and a printable study guide. Any text on the page can be highlighted to be read aloud or explained in detail. The Blob mascot is drawn on canvas; its colour follows the mode and its accessories (monocle and mustache, lightning bolt, hacker faceplate, glasses and tie, cube, masquerade mask) follow the style, all eased smoothly between states.

7Security review

Because the app can execute code (/api/run), a local web server is an attack surface: any website open in the same browser could try to send requests to 127.0.0.1. Two defences are in place: a Host-header allow-list (against DNS rebinding) and an Origin-header check on all state-changing requests (against cross-site request forgery). The Origin check was added after a review found that the Host check alone did not stop a cross-site POST; tests confirm a foreign origin now receives 403 while the app's own page still runs code. Other measures: binding to 127.0.0.1, HTML escaping of model output, sanitised ids in file paths, upload limits, magic-byte checks for wallpapers, isolated and time-limited code runs, and name-checked process termination.

11Limitations and future work

  • Prompt reading speed. Reduce Offline prompts (3 passages, shorter chunks), try the Vulkan build on the Vega 8, or keep a warm prompt cache per book.
  • Scanned books. Pages without a text layer are skipped; an OCR pass at indexing time would include them.
  • Model size. 3B models reason less reliably than larger ones; the 5 GB limit allows 7B/8B models at about half the speed.
  • Evaluation. A fixed question set with expected pages would measure retrieval accuracy over time (the G014 project had one).
  • Windows-only parts. OCR, the Job Object and some voice paths are Windows-specific; the rest runs on Linux and macOS.
  • Memory curation. Auto-learn can save trivial facts; a periodic merge or review step would keep memory tidy.
